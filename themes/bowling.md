- **설정창 표시 이름**: `"볼링공"`

## 1. 컨셉 / 디자인
- 파란 마블(대리석) 무늬 볼링공. 참고 이미지(`image/볼링공.png`)의 9종 느낌.
- **단단한 공(Rigid)** — 당구공처럼 찌그러지지 않는다(표정·열림 이펙트 없음).
- 핵심 특징: **굴러가면 표면 무늬가 바뀐다.**
  9가지 면(마블 소용돌이 + 손가락 구멍 배치: 3구/2구/무구멍)을 미리 만들어 두고,
  공이 굴러간 거리를 "공 지름 기준 회전수"로 환산해 면을 넘긴다.
  한 바퀴(1.0 회전)를 굴러가는 동안 9면을 모두 지나가고, 진행 방향(좌/우)에 따라 넘기는 방향이 바뀐다.

## 3. 구현 메모
- **베이스 구체**: 당구공 스킨과 동일한 `RadialGradientBrush`(좌상단 광원) 방식, 파랑(`#2C79C0`).
- **마블 무늬**: 84×84 원형 클립 안에, 시드 고정 `Random` 으로 물결치는 스트로크(`Path`+`PolyLineSegment`)를
  밝은 소용돌이(넓게) → 중간 톤 → 얇고 옅은 정맥(음영) 순으로 겹치고, `BlurEffect`(2.1) 로 번지게 해
  흐르는 대리석 느낌을 낸다. 스트로크는 가장자리 밖까지 쓸어 클립돼 끝이 안 보인다.
- **손가락 구멍**: 깊이감을 준 `RadialGradientBrush`(위쪽 살짝 밝은 림) 원. 면마다 개수/위치가 다르다.
- **9면 교체**: 9개 `Canvas` 레이어를 `PatternHost` 에 넣고 하나만 `Visible`.
  `OnRoll(revolutions)` 이 누적 회전수를 받아 면당 `1/9` 회전마다 다음/이전 면으로 넘긴다(유휴 시 비용 0).
- **참고**: 기존 `BilliardSkin`(Rigid 구체 구조), `BallSkin`(코드 생성 데코) 구조를 참고.

## 5. 볼링하기 모드 (레인 + 10핀)
공 **우클릭 → 볼링하기 🎳** 로 주 모니터에 볼링장을 세팅한다. (볼링공 테마일 때만 메뉴 노출)

**신규 파일**
- `Views/Skins/PinSkin.xaml(.cs)` — 통통한 흰 볼링핀(빨간 목 줄무늬) + 넘어짐(tip-over) 회전 애니메이션.
- `Views/PinWindow.xaml(.cs)` — 핀 물리 창(클릭 통과). 창 크기=SlimeSize(물리 일관), 핀은 안에 작게. `Knock(dir)` 로 쓰러뜨림.
- `Views/LaneOverlayWindow.xaml(.cs)` — 원근 레인 오버레이(클릭 통과). 사다리꼴 레인·거터·수렴 결·조준 화살표·파울라인·핀덱 + 점수판.

**SlimeWindow 추가**
- 우클릭 메뉴 3종(볼링하기 / 핀 다시 세우기 / 볼링 끝내기) + `OnMenuOpened` 노출 제어.
- `ComputeBowlingLayout()` — 원근 지오메트리(위=핀쪽 좁고, 아래=투구쪽 넓음) + 10핀 삼각.
- `OnBowlingTick` 볼링 물리 루프 + `ResolveBowlingCollisions`(공 무겁고 핀 가벼움; 질량차로 핀이 튕김) + `ConfineToLane`(가둠).
- 스킨 변경/종료 시 `ExitBowling` 로 정리.

**규칙(요청 반영)**
1. **공 가둠**: 공은 파울 라인 아래로 못 내려가고, 레인(거터 포함) 밖으로 못 나간다. 매 프레임 `ConfineToLane` 로 원근 벽에 감쇠 반사.
2. **두꺼운 핀 + 연쇄**: 핀 실루엣을 통통하게, 반경 `S*0.30`(공 `S*0.42`). 핀 간격을 촘촘히(`hGap=S*0.72`) 두어 하나가 쓰러지면 이웃도 연쇄로 넘어진다. 핀도 레인 안에 갇혀 예전처럼 화면 전체로 비산하지 않는다.
3. **거터 + 기본 크기**: 레인 양옆 사다리꼴 거터를 그린다. 볼링 진입 시 크기를 **기본값(96)** 으로 강제하고, 종료 시 사용자 크기로 복원(`_savedSlimeSize`).
4. **원근감**: 레인을 사다리꼴(위 좁음/아래 넓음)로, 나무 결·거터도 소실점으로 수렴하게 그려 원근을 표현.

**점수**: 쓰러진 핀 수를 상단에 표시, 10개면 `STRIKE!`, 거터볼이면 `거터! 😵`.

### 5-1. 추가 규칙 (2차 요청 반영)
1. **핀이 깨져 보이던 문제 수정** — 원인은 핀 창(`SlimeSize` 정사각)이 작아서, 80° 넘어질 때 핀이 **창 밖으로 나가 잘린** 것.
   `PinWindow` 를 핀의 2배 크기(`PadFactor=0.5`)로 만들고 핀을 중앙 배치, `ApplyPosition` 에서 패딩만큼 보정.
   이제 서 있던 모양 그대로 밑동을 축으로 온전히 넘어진다.
2. **파울선 규칙 강화** — 공 시작 위치를 파울선 바로 위(`foulY - S*0.42`)로. 가둠(`UpdateBallLane`)을
   물리 틱뿐 아니라 **메인 렌더 루프**에도 적용하고, **드래그·잡기 경로**에도 `ClampBallForPlacement` 를 넣어
   어떤 방법으로도 파울선/레인 밖으로 못 나가게 했다. 파울선은 튕기지 않고 벽처럼 멈춘다.
3. **거터 구현** — 거터 폭을 **공 지름(`S*1.05`)** 으로 키웠다(원근에 맞춰 위쪽은 비례 축소).
   공이 레인 가장자리를 넘으면 **거터에 빠진 상태로 전환**되어:
   - 좌우 이동 불가(홈 중심선에 락) + 회전 정지 → 홈을 따라 앞으로만 굴러간다
   - 홈 끝(뒷벽)에 닿으면 되돌아오지 않고 그대로 멈춘다
   - **핀과 충돌하지 않는다**(거터볼 = 0점) — 충돌 루프에서 공을 제외
   - 한 번 빠지면 레인으로 복귀 불가. 새 투구(핀 다시 세우기/잡기)에서 해제
### 5-3. 게임 규칙 (3차 요청 반영)
1. **기름칠 레인** — 볼링 진입 시 `AppSettings.Friction` 을 `0.9 → 0.35` 로 낮춘다(종료 시 복원).
   매끄럽게 굴러가되 **던진 세기는 그대로 반영**되므로 살살 굴리면 끝까지 못 간다.
   핀은 저마찰의 영향을 받지 않도록 별도 감쇠(`exp(-3.0*dt)`).
   - ⚠️ 최소 속도 보정은 **넣지 않는다**(놓기만 해도 튀어나가는 문제).
   - 사용자의 `ThrowPower`(던지기 가중치)가 크면 살짝 놓아도 증폭되므로, 볼링에서는
     `ApplyBowlingLaunch()` 가 속도를 `ThrowPower` 로 나눠 **1.0x 로 상쇄**한다.
     설정값 자체는 건드리지 않는다 — 자동저장이 사용자 값을 덮어쓰기 때문.
2. **투구 후 자동 복귀** — 공이 레인 끝에 닿거나 멈추고 핀도 정지하면 0.8초 뒤 `FinishThrow()` →
   점수 집계 후 공을 **시작점(파울선)** 에 다시 놓는다.
3. **거터도 끝까지** — 거터에 빠지면 홈을 따라 끝까지 굴러가고(되돌아오지 않음), 끝에 닿으면
   투구 종료로 처리되어 공이 시작점으로 복귀한다. 거터볼은 핀과 충돌하지 않아 0점(`거터! 😵`).
4. **10프레임 × 2구** — `_frame`(1~10) / `_throwNo`(1~2) / `_totalScore` 관리.
   - 1구에 10개 → `STRIKE!` → 다음 프레임(핀 10개 재배치)
   - 1구에 일부만 → **쓰러진 핀만 치우고(`RemoveKnockedPins`) 남은 핀은 그 자리 그대로** → 2구
   - 2구에 남은 핀을 모두 → `SPARE!`
   - 10프레임 종료 → `게임 종료! 총 N점` (우클릭 → 핀 다시 세우기 로 새 게임)
   - HUD: `4F · 2구 · 25점` 형식으로 레인 상단에 표시.
6. **파울선 위치** — 공 시작점은 파울선 **뒤(6시 방향, `foulY + S*0.58`)** 의 준비 구역.
   세로 가둠 하한을 `BotY - r` 로 두어 **파울선 뒤로 자유롭게 오갈 수 있고**, 넘지 못하는 것은
   핀 뒤 벽뿐이다. 거터는 파울선 너머(레인 위)에서만 작동한다.

### 5-2. 핀 리디자인
- **실루엣**: 높이:최대폭 ≈ **3:1**. 둥근 머리에서 가는 목, 넓은 어깨와 배, 안정적인 밑동으로 이어지는 S 곡선.
- **재질**: 따뜻한 백색 중앙광 + 청회색 가장자리 음영 + 어깨 유광으로 도자기 질감을 표현.
- **목 줄무늬**: 검정 구분선 대신 입체적인 빨간 그라데이션 2줄과 가는 암적색 테두리.
- **윤곽**: 굵은 검정선 대신 1.65px 청회색 외곽선을 사용해 작은 크기에서도 선명하지만 덜 만화적으로 보이게 조정.
- **핀덱 배율**: `PinWindow.VisualScale = 0.72` 로 10핀이 과하게 겹치던 문제를 완화. 창 크기는 그대로 유지해 넘어질 때 잘리지 않는다.
- **물리 보존**: 표시 배율과 별개로 `CollisionWidth = 44` 를 사용해 기존 연쇄 충돌 감각을 유지.

### 5-3. 레인 리디자인
- 20개 판재의 교차 착색과 수렴 이음선으로 목재 밀도와 원근감을 강화.
- 거터를 깊은 홈·바깥 레일·안쪽 립의 3단 구조로 구성하고, 핀덱 뒤에는 어두운 피트를 추가.
- 중앙 오일 반사, 조준 다트, 어프로치 도트, 청회색 파울 라인을 적용.
- 점수는 금색 테두리의 반투명 HUD 패널로 묶어 어떤 바탕화면에서도 읽히도록 개선.

### 5-4. 모니터형 10프레임 점수판
- 주 모니터 **우측 상단**에 볼링장 천장 모니터를 본뜬 전용 `BowlingScoreboardWindow` 표시.
- 은색 베젤·남색 화면·노란 현재 프레임·하단 상태/총점 배지 구성.
- 1~10프레임의 투구 마크(`X`, `/`, `–`, 핀 수)와 확정된 누적 점수를 실시간 표시.
- 스트라이크/스페어 보너스를 포함한 표준 누적 점수 계산. 10프레임은 조건에 따라 3번째 보너스 투구까지 진행.
- 기존 레인 중앙 HUD는 제거해 핀과 투구 경로를 가리지 않도록 함.
4. **터널링 수정(중요)** — 빠른 공이 핀 사이를 **한 프레임에 뛰어넘어 그냥 통과**하던 버그.
   볼링 틱에서 지난 프레임 위치→현재 위치를 `(rBall+rPin)*0.5` 간격의 **서브스텝**으로 나눠 충돌을 검사한다.
   이 수정 후 직구가 정상적으로 핀을 맞히고 연쇄로 STRIKE 가 난다.

## 6. 남은 일 / 알려진 이슈
- 드래그로 들고 옮기는 동안(속도 0, 위치 직접 배치)에는 면이 바뀌지 않는다("굴러갈 때"만 변경 — 의도).
- 핀은 원근 레인 위에서 크기 일정(깊이별 스케일 미적용). 필요하면 깊이 스케일 추가 가능.
- 가운데 정타는 촘촘한 배치 특성상 스트라이크가 잘 난다(연쇄 강조 요청 반영). 난도를 원하면 `hGap`/질량/반발 조정.
